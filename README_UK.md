# UA-Piper-TTS

Rust-проект для генерації аудіо з тексту українською мовою.

## Як це працює

Rust викликає **Piper TTS** (CLI) через subprocess.
Перед синтезом текст нормалізується чистим Rust-кодом з використанням крейту `num2words`:
- Числа → українські слова (25 → "двадцять п'ять")
- Спецсимволи → слова (°C → "градусів це́льсія" з наголосом)
- Великі літери → маленькі (модель не підтримує uppercase)

## Формат аудіо

| Формат | Умова | Параметри |
|--------|-------|-----------|
| **MP3** | встановлено `ffmpeg` | 32 kbps, моно, 22.05 kHz |
| **WAV** | `ffmpeg` відсутній | PCM WAV (без стиснення, 22050 Hz) |

Формат визначається автоматично при запуску. MP3 з бітрейтом 32 kbps забезпечує чітку якість мовлення при малому розмірі файлу (~8 KB за фразу).

## Веб-сервер (REST API)

### Запуск

```bash
cargo run
```

### Конфігурація (`config.json`)

```json
{
    "output_dir": "./output",
    "port": 9000,
    "host": "0.0.0.0",
    "speaker_id": 2,
    "model_dir": "./models/piper-uk_UK-dmytro-medium"
}
```

### Ендпоінти

| Метод | Шлях | Опис |
|-------|------|------|
| `GET` | `/health` | Стан сервера |
| `POST` | `/tts` | Генерація аудіо |
| `GET` | `/output/{filename}` | Завантаження аудіо-файлу |

### Тіло запиту TTS

```json
{
  "text": "Привіт світе",
  "overwrite": false,
  "filename": "custom_name"
}
```

| Параметр | Обов'язковий | Опис |
|----------|--------------|------|
| `text` | Так | Текст для озвучки |
| `overwrite` | Ні | `true` = перегенерувати навіть якщо файл існує (за замовчуванням: false) |
| `filename` | Ні | Кастомне ім'я файлу (без розширення). Автогенерація з тексту якщо пропущено. |

### Приклад запиту

```bash
curl -X POST http://localhost:9000/tts \
  -H "Content-Type: application/json" \
  -d '{"text": "Привіт світе", "overwrite": false}'
```

### Приклад відповіді

```json
{
  "success": true,
  "filename": "Привіт світе.mp3",
  "message": "Аудіо згенеровано успішно",
  "already_exists": false
}
```

Параметр `overwrite`: `true` — перегенерувати файл, `false` — пропустити якщо існує.

## Встановлення

### Вимоги
- Linux (x86_64 або aarch64)
- Python 3.8+ (тільки для Piper CLI)
- Rust 1.70+

### Швидке встановлення (рекомендовано)

Одна команда для встановлення залежностей, збірки, розгортання та запуску:

```bash
./scripts/quickstart.sh
```

### Ручне встановлення

#### Крок 1: Встановлення залежностей

```bash
./scripts/install_deps.sh
```

Скрипт автоматично:
- Визначить архітектуру (x86_64, aarch64, armv7)
- Встановить системні пакети (gcc, openssl, ffmpeg тощо)
- Встановить Rust (якщо відсутній)
- Встановить Piper TTS
- Запропонує завантажити українську модель

#### Крок 2: Збірка

```bash
# Release збірка для поточної архітектури
./scripts/build.sh

# Крос-компіляція для ARM64
./scripts/build.sh -a aarch64

# Крос-компіляція для ARMv7
./scripts/build.sh -a armv7

# Чиста збірка
./scripts/build.sh -c
```

#### Крок 3: Розгортання та запуск

```bash
# Встановити як systemd сервіс (потрібен sudo)
sudo ./scripts/deploy.sh install

# Запустити сервіс
sudo ./scripts/deploy.sh start

# Перевірити статус
./scripts/deploy.sh status

# Переглянути логи
sudo ./scripts/deploy.sh logs -f
```

### Альтернатива: Запуск напряму

```bash
cargo run
```

Сервер запуститься на `http://0.0.0.0:9000`. Аудіо зберігається у `output/`.

## Управління сервісом

Після розгортання через `./scripts/deploy.sh install`:

| Команда | Опис |
|---------|------|
| `sudo ./scripts/deploy.sh start` | Запустити сервіс |
| `sudo ./scripts/deploy.sh stop` | Зупинити сервіс |
| `sudo ./scripts/deploy.sh restart` | Перезапустити сервіс |
| `./scripts/deploy.sh status` | Перевірити статус |
| `sudo ./scripts/deploy.sh logs -f` | Переглянути логи |
| `sudo ./scripts/deploy.sh uninstall` | Видалити сервіс |

Сервіс працює від системного користувача `tts` з увімкненим захистом.

## Оновлення

Для оновлення до останньої версії:

```bash
# Притягти зміни, перезібрати та перезапустити
./scripts/update.sh

# Оновити з конкретного бранчу
./scripts/update.sh -b develop

# Примусова перезбірка навіть без нових комітів
./scripts/update.sh -f

# Пробний запуск — показати що буде зроблено
./scripts/update.sh -n
```

Скрипт оновлення:
1. Перевірить що ви в корені проекту
2. Перевірить що сервіс розгорнуто
3. Притягне зміни з GitHub (зупиниться якщо змін немає)
4. Перезбере проект
5. Оновить та перезапустить сервіс

## Нормалізація чисел

| Ввід | Вимовляється як |
|------|-----------------|
| `25°C` | двадцять п'ять градусів це́льсія |
| `36.6°C` | тридцять шість **і** шість градусів це́льсія |
| `9.6°C` | дев'ять цілих шість десятих градусів це́льсія |
| `-5°C` | мінус п'ять градусів це́льсія |
| `100%` | сто відсотків |
| `$50` | п'ятдесят доларів |
| `#123` | номер сто двадцять три |
| `3.14` | три цілих чотирнадцять сотих |

### Правило температури
- Ціла частина **> 9**: короткий формат `"36 і шість"`
- Ціла частина **≤ 9**: повний формат `"дев'ять цілих шість десятих"`


## Логування помилок

Програма автоматично перехоплює помилки від Piper TTS і записує їх у файл `tts_errors.log`.

### Формат запису

```
[повідомлення про помилку від Piper] | [текст, що викликав помилку]
```

Це дозволяє:
- Швидко знайти проблемні місця в тексті
- Мати повний контекст для аналізу помилки
- Виправити текст або налаштування моделі
