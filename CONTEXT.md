# CONTEXT — Sherpa-UA TTS

> Довготривалий контекст проекту. Тут зберігається вся важлива інформація, історія рішень, правила розробки та відомі проблеми.

---

## 📋 Про проект

**Мета:** Генерація аудіо з тексту українською мовою через Rust.
**Платформа:** Linux aarch64 (Rockchip RK3588), але працює і на x86_64.
**Мова:** Rust (основна), Piper CLI (субпроцес).

## 🏗 Архітектура

```
┌─────────────┐     ┌────────────────┐     ┌────────────┐
│   Rust код  │────▶│ normalize.rs   │────▶│  Piper CLI │
│  main.rs    │     │ (num2words)    │     │  (subproc) │

                           │                      │
                      Нормалізований        WAV файл
                      текст (нижній         в output/
```

### Ключові компоненти

| Файл | Призначення |
|------|-------------|
| `src/main.rs` | Виклик Piper CLI через subprocess, ввід тексту в stdin |
| `src/normalize.rs` | Нормалізація: числа → слова, спецсимволи → слова, наголоси |
| `download_models.sh` | Завантажує Piper модель з HuggingFace |
| `models/piper-uk_UK-dmytro-medium/` | ONNX модель + espeak-ng дані |

### Залежності

```toml
hound = "3.5"       # WAV (зараз не використовується, але залишено)
num2words = "1.2"   # Конвертація чисел → українські слова
```

### Зовнішні залежності (не Rust)

- **piper-tts** (`pip3 install piper-tts`) — надає `piper` CLI бінарник
- **ONNX Runtime** — встановлюється автоматично з piper-tts

## 🗣 Модель

### Piper `uk_UA-ukrainian_tts-medium`

- **Джерело:** https://huggingface.co/rhasspy/piper-voices
- **Розмір:** ~74 MB
- **Sample rate:** 22050 Hz
- **Спікери:** 3
  - `0` — lada (жіночий)
  - `1` — mykyta (чоловічий)
  - `2` — tetiana (жіночий) ← **за замовчуванням**

### Відомі обмеження моделі

1. **Не підтримує великі літери** — текст завжди конвертується в нижній регістр
2. **Попередження `Missing phoneme: П/С`** — виникає коли текст не конвертовано в нижній регістр
3. **Наголоси** — підтримуються через U+0301 Combining Acute Accent (`це́льсія`)
4. **espeak-ng дані** потрібні для фонемізації (скопійовані з іншої моделі)

## 📝 Нормалізація тексту

### Бібліотека: `num2words` (Rust крейт)

Конвертує числа в українські слова з правильною граматикою.

### Правило десяткових для температури (°C)

| Ціла частина | Формат | Приклад |
|--------------|--------|---------|
| **> 9** | `"і [цифра]"` | `36.6°C` → `"тридцять шість і шість градусів це́льсія"` |
| **≤ 9** | `"цілих ... десятих/сотих"` | `9.6°C` → `"дев'ять цілих шість десятих градусів це́льсія"` |
| Звичайні числа (без °C) | Завжди `"цілих ..."` | `3.14` → `"три цілих чотирнадцять сотих"` |

### Підтримувані спецсимволи

| Символ | Заміна |
|--------|--------|
| `°C` / `°c` | ` градусів це́льсія` |
| `°F` / `°f` | ` градусів фаренгейта` |
| `°` (без літери) | ` градусів` |
| `%` | ` відсотків` |
| `$` | ` доларів` |
| `#` | ` номер ` |
| `+` | ` плюс ` |
| `=` | ` дорівнює ` |
| `&` | ` і ` |

### Апостроф

`num2words` використовує U+02BC (`ʼ`), але Piper розуміє тільки U+0027 (`'`).
Вирішення: `.replace('ʼ', "'")` після кожної конвертації.

## 🐛 Відома історія проблем та рішень

### 1. "Обрізане" аудіо (0.5с замість 3с)
**Причина:** VITS моделі з `characters` frontend не обробляють `add_blank` коректно в sherpa-onnx.
**Рішення:** Відмовились від sherpa-onnx VITS на користь Piper.

### 2. "АААУУУ" замість мовлення
**Причина:** Piper CLI через stdin pipe генерував пошкоджене аудіо на деяких системах.
**Рішення:** Перевірено — Piper CLI працює коректно. Проблема була в іншому.

### 3. "Сьогодні" → "йогодні"
**Причина:** Велика 'С' пропускалась моделлю (немає в phoneme_id_map).
**Рішення:** `.to_lowercase()` перед подачею в Piper.

### 4. "цельсія" → "цельсІя" (неправильний наголос)
**Причина:** Модель ставила наголос на останній склад.
**Рішення:** Додано U+0301 після 'е': `це́льсія`.

### 5. "шість кома шість" замість "шість цілих шість десятих"
**Причина:** num2words за замовчуванням використовує формат "кома ...".
**Рішення:** Власна логіка `decimal_to_ua()` з правильними суфіксами.

### 6. Python-зоопарк
**Причина:** Спочатку використовувався Python-скрипт для нормалізації.
**Рішення:** Перенесено все в Rust через крейт `num2words`.

## 📐 Правила розробки

1. **Тільки Rust + Piper CLI** — жодних Python-скриптів в основному потоці
2. **Нормалізація в Rust** — `num2words` крейт для чисел
3. **speaker_2 за замовчуванням** — tetiana (жіночий голос)
4. **Нижній регістр** — обов'язково перед подачею в Piper
5. **Наголоси** — U+0301 для ключових слів (це́льсія)
6. **Тести** — кожна зміна в `normalize.rs` має супроводжуватись тестами
7. **Збірка** — `cargo build` має проходити без warning-ів

### Як додати новий спецсимвол

1. В `normalize.rs` знайти блок `while let Some(c) = chars.next()`
2. Додати `else if` для нового символу
3. Додати тест в `mod tests`

### Як додати нову модель

1. Оновити `MODELS` в `main.rs`
2. Оновити `download_models.sh`
3. Перевірити що `model.onnx` та `model.onnx.json` існують
4. Перевірити наявність `espeak-ng-data/`
